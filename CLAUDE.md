# About activity-store

## What it owns

`:8336`, loopback only. What the user did online: one activity (`activity_000001`) per thing done at one time — a search, a page visited, a video watched, an app used, a place looked up — with Google's product, a verb from `GET /vocabularies`, the title or query, the url, the time (epoch seconds, UTC), where the user was when the source recorded it, and Google's further lines as structured `details`. Also the files that came with an activity (`attachment_000001`, voice-search recordings and pictures, kept under `<data dir>/attachments`, never in SQLite) and the imports that brought it in (`import_000001`). Activity ids are registered in kanban-store's entity-type registry as type `activity`, so a journal-store timeline or a note cites one as a chip; dash's resolver fetches it here. `GET /days/{YYYY-MM-DD}?tz=` summarizes a day by product for a timeline or the weekly location job. **Activity history is private**: a front door such as dash adds the auth this service has none of, and nothing here is copied to noteboard. `CONTRACT.md` is the route table.

# How it works

## Imports, folding and times

`activity-import-google -dir <takeout dir> [-dry-run]` reads every `My Activity/<Product>/*.html` (filed under the directory's name), YouTube's `history/*.html` (the same HTML, filed under `YouTube`), `Chrome/History.json` and `Chrome/Bookmarks.html`, each file as its own import through `internal/importclient`: `POST /imports` with the file's sha256 (a finished hash is a no-op, an unfinished one resumes), `POST /imports/{id}/batches` of 2000 records in one transaction each, `POST /imports/{id}/finish`. Parsing is all in `internal/takeout`, which decides nothing about storage; matching is all in `store_imports.go`. A record whose `(source, source_ref)` is a known sighting changes nothing; one whose url and second match an activity from another source, or from the same product in another import, is **folded** into it as a sighting (a YouTube watch in My Activity and in YouTube's history, a page in My Activity's Chrome page and in `History.json`); two products of one source stay apart, as Google keeps them. `source_ref` is a hash or a time plus a url hash, never the record's words, so a purge leaves nothing readable behind. My Activity times end in a zone abbreviation that Takeout applies as a **fixed offset to every date in the file** (a January search in a summer export says PDT and means UTC-7; measured against Chrome's UTC history); `internal/takeout/googletime.go` reads it that way and refuses an unknown or ambiguous abbreviation. A card's opening words map to an action through `ActionPhrases` in `vocabulary.go`; words it does not know give `other`, kept in `action_text` and `title`. Not read: Takeout's Access Log, Play Store JSON, YouTube comments, live chats, subscriptions and playlists, Chrome's open-tab sessions, and files beside a My Activity page that no card names (the importer lists them). Which export this host's data came from is not in this repo: see the noteboard note tagged `activity-store`.

## Delete, purge and attachments

Records are not edited by hand, so there is no PATCH. `DELETE /activities/{id}` is soft and `restore` undoes it, each after copying the whole activity to `revisions`. `POST /activities/{id}/purge` is for something that must not be kept: it blanks the title, url, words, details and location in the row and every revision, deletes the full-text row (the FTS5 table is contentless, so the index holds no copy of the text) and the attachment files no live attachment shares, and marks the activity deleted and purged. The row, its sightings and its `dedupe_key` stay, so a citation still resolves and a later import folds into the purged row instead of bringing it back. A purged activity cannot be restored (409) and its attachments answer 410.

# Working in this repo

## Build, test and deploy

Module `github.com/kayushkin/activity-store`, root package `activitystore`, server `cmd/activity-store`, importer `cmd/activity-import-google`. **Every build and test needs `-tags sqlite_fts5`**: without it the build succeeds and the service dies at boot with `no such module: fts5`. `go.mod` replaces `../llm-bridge` (settings). Every variable it reads is declared once in `settings.go` with llm-bridge `servicesettings`, served at `GET /settings`; `TestEveryEnvironmentVariableTheServiceReadsIsDeclared` fails on an undeclared `os.Getenv`. `./deploy.sh` runs the shared deploy gate, tests, checks the running unit's environment, installs `activity-store` and `activity-import-google` to `~/bin`, restarts the user unit and fails unless `/health` is ok and the port is bound to loopback only. `./generate-ts.sh` renders `activity.go` and `vocabulary.go` to `ts/model.ts`, published source-only as `@kayushkin/activity-store-types` (`file:../activity-store/ts`); bridge-ui's activity chip reads it.

## Public repository: nothing personal

This repo is public. Nothing about the user's own data goes in it — not in code, tests, comments, commit messages or this prompt: no real searches, sites, videos, channels, coordinates, place names, machine names, file paths of their exports, account names, home directories or tokens. Tests use invented data (`sourdough starter`, `Example Channel`, coordinates near 10°N 20°E). A fact an agent here needs about this host's data goes in a noteboard note tagged `activity-store`.
